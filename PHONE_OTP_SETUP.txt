OMNIVIEW CONTRIBUTORS - PHONE SIM OTP SETUP
Prepared: 13 September 2026

CURRENT STATUS
Phone login is disabled. The app already asks Supabase to generate and verify
SMS codes, but the delivery gateway and Supabase Send SMS hook are not connected.
Installing the phone app alone does not activate OTP delivery.

RECOMMENDED TEAM-TEST ARRANGEMENT
Use a spare Android phone with your SIM as the sender. Contributors do not need
to install a gateway on their phones. Supabase generates and checks the code;
your sender phone sends it through its SIM. SMS charges and limits still come
from your mobile plan. Keep the sender phone charged and online during testing.

STEP 1 - PREPARE YOUR SENDER PHONE
1. Insert an active SIM and send one ordinary SMS manually to a teammate.
2. Connect the phone to reliable Wi-Fi or mobile data.
3. If you have two SIMs, decide which one should send the codes.

STEP 2 - INSTALL THE GATEWAY
1. Open https://docs.sms-gate.app/installation/ on the Android phone.
2. Follow its official GitHub Releases link and install the standard APK.
3. Allow SMS sending. Allow phone-state access if you need SIM selection.
4. This task only needs outgoing SMS; incoming-message forwarding is unnecessary.
5. Keep the app allowed to run in the background. If the phone stops it while
   locked, allow background activity in Android's app/battery settings.

STEP 3 - CONNECT YOUR PHONE TO THE INTERNET GATEWAY
1. Open SMS Gateway for Android and enable Cloud Server.
2. Start the connection and wait for Online.
3. Store the generated gateway username and password privately.
4. The cloud endpoint is https://api.sms-gate.app/3rdparty/v1/messages
5. Use the gateway dashboard, https://dashboard.sms-gate.app, to send a harmless
   test message to your own number. Confirm the message really arrives.
   Dashboard acceptance alone is not proof of delivery.
Reference: https://docs.sms-gate.app/getting-started/public-cloud-server/

STEP 4 - PREPARE ENCRYPTION BEFORE REAL OTP MESSAGES
Cloud mode relays messages through SMSGate's server. Configure its end-to-end
encryption so the relay does not receive the OTP and recipient in plain text.
Choose a long encryption passphrase in the phone's encryption settings and save
the same value privately for the backend integration. The backend must encrypt
both message text and recipient numbers and set isEncrypted=true.
Reference: https://docs.sms-gate.app/privacy/encryption/
Alternative: run SMSGate's private server if you want to host the relay yourself:
https://docs.sms-gate.app/getting-started/private-server/

STEP 5 - COMPLETE THE BACKEND BRIDGE (DEVELOPER STEP STILL REQUIRED)
Provide the gateway mode, username/password, encryption passphrase, and selected
SIM/device information through deployment secrets, never a public repository.
The developer must add and test a Supabase Send SMS hook handler that:
- Verifies Supabase's webhook signature before processing the request.
- Reads the recipient from user.phone and the code from sms.otp.
- Sends an encrypted request to the gateway using server-only credentials.
- Returns success only after the gateway accepts the request.
- Handles timeouts and rejects invalid signatures without sending SMS.
- Avoids logging OTPs and restricts the team test to your test phone numbers.
No working hook URL is supplied here because this bridge is not implemented yet.
Reference: https://supabase.com/docs/guides/auth/auth-hooks/send-sms-hook

STEP 6 - CONNECT SUPABASE AFTER THE BRIDGE IS DEPLOYED
1. Open your Supabase project > Authentication > Auth Hooks.
2. Add a Send SMS hook with the deployed handler URL.
3. Put the hook signing secret in that handler's server environment.
4. Enable the Phone provider under Authentication > Sign In / Providers.
5. Keep phone confirmation enabled. Let Supabase generate/expire/verify codes.
6. Test the hook before switching on the Contributors app's phone option.

STEP 7 - ENABLE AND TEST THE CONTRIBUTOR FLOW
1. In Render, set VITE_PHONE_AUTH_ENABLED=true and rebuild/redeploy the app.
2. Open the app, choose Phone number and enter a number including +91.
3. Request one code, confirm receipt, and sign in using that code.
4. Check that an incorrect or expired code fails.
5. Turn the sender phone offline and test failure/recovery. Do not claim delivery
   until it arrives; queueing and handset delivery are separate events.
6. Repeat with the other teammates and check that their footage stays separate.

IF IT DOES NOT WORK
- No SMS: check SIM balance, signal, SMS permission and the selected SIM.
- Works only while unlocked: check Android background/battery restrictions.
- Gateway accepts but no delivery: inspect its delivery status on the phone.
- Decryption error: check the same encryption passphrase on phone and backend.
- Supabase rejects request: inspect hook signature/configuration and rate limits.
- App still says disabled: rebuild after changing the VITE_ setting.

LOCAL MODE NOTE
A 192.168.x.x phone address cannot be reached directly from Render. Local Server
mode needs a properly protected network connection from the backend. Cloud mode
avoids that network setup for this small test.
Reference: https://docs.sms-gate.app/getting-started/local-server/
